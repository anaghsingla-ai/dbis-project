# CampusHire — REST API Specification (Python Flask)

Base URL: `http://localhost:5000/api`  
Authentication: Bearer JWT token in `Authorization: Bearer <token>` header or `token` cookie.

---

## 1. Authentication (`/api/auth`)

### `POST /api/auth/login`
- **Request:**
  ```json
  { "username": "admin", "password": "password123" }
  ```
- **Response (200):**
  ```json
  {
    "success": true,
    "token": "eyJhbGciOi...",
    "user": {
      "user_id": 1,
      "username": "admin",
      "email": "kavita@tpo.example",
      "role": "TPO_ADMIN",
      "full_name": "Mrs. Kavita Joshi (TPO Head)"
    }
  }
  ```

### `GET /api/auth/me`
- Requires Bearer Token. Returns active user profile with linked entity details (`student`, `company`, `department`, or `officer`).

### `GET /api/auth/demo-accounts`
- Returns preset quick-login credentials for all 4 roles.

---

## 2. Admin Endpoints (`/api/admin`)
*All endpoints require role `TPO_ADMIN`.*

- `GET /api/admin/stats`: Returns placement metrics, CTC averages, salary brackets, and department placement charts.
- `GET /api/admin/students`: Filterable student roster (`dept_id`, `search`, `min_cgpa`, `max_backlogs`, `placed`).
- `POST /api/admin/students`: Registers student via procedure **T1** (`sp_register_student`).
- `POST /api/admin/drives`: Creates drive and criteria atomically via procedure **T2** (`sp_create_drive`).
- `POST /api/admin/offers`: Issues offer via procedure **T5** (`sp_issue_offer`).
- `GET /api/admin/reports/placement`: Runs snapshot procedure **T10** (`sp_placement_report`) returning 3 result sets.
- `GET /api/admin/audit-logs`: Fetches trigger-generated records from `Audit_Log`.

---

## 3. Student Endpoints (`/api/student`)
*All endpoints require role `STUDENT`.*

- `GET /api/student/overview`: Active application count, offer tally, and upcoming selection rounds.
- `GET /api/student/drives`: Lists drives and computes each student's eligibility with a SQL `CASE` expression.
- `POST /api/student/apply`: Submits application via procedure **T3** (`sp_apply_to_drive`).
- `GET /api/student/applications`: Returns submitted applications and selection round outcomes.
- `POST /api/student/withdraw`: Withdraws application via procedure **T7** (`sp_withdraw_application`).
- `GET /api/student/offers`: Lists offers issued to this student.
- `POST /api/student/offers/respond`: Accepts or declines an offer via procedure **T6** (`sp_respond_to_offer`).

---

## 4. Company HR Endpoints (`/api/hr`)
*All endpoints require role `COMPANY_HR`.*

- `GET /api/hr/overview`: Company recruitment stats, active drives, shortlisted candidates.
- `GET /api/hr/drives`: Drives belonging to the HR's company.
- `GET /api/hr/rounds/<round_id>/candidates`: Candidates eligible to be evaluated for this round.
- `POST /api/hr/rounds/record-result`: Evaluates candidate via procedure **T4** (`sp_record_round_result`), firing trigger **TR15**.

---

## 5. Department Coordinator Endpoints (`/api/coordinator`)
*All endpoints require role `DEPARTMENT_COORDINATOR`.*

- `GET /api/coordinator/overview`: Department headcount, placement ratio, and salary metrics.
- `GET /api/coordinator/students`: Roster of students in coordinator's department.
- `POST /api/coordinator/students/academic-record`: Updates CGPA and backlogs via procedure **T8** (`sp_update_academic_record`).
- `POST /api/coordinator/students/transfer`: Transfers student via deadlock-safe procedure **T9** (`sp_transfer_student_dept`).
- `GET /api/coordinator/audit-history`: Department-specific audit history generated by trigger **TR4**.

---

## 6. DBMS Demonstration Lab (`/api/dbms-lab`)
*Requires role `TPO_ADMIN`.*

- `GET /api/dbms-lab/transactions`: Schema metadata for procedures T1 through T10.
- `GET /api/dbms-lab/triggers`: Schema metadata for triggers TR1 through TR18.
- `POST /api/dbms-lab/execute`: Arbitrary procedure runner with before/after state capture.
- `POST /api/dbms-lab/run-scenario`: Executes evaluation scenarios (`DEMO_1_ELIGIBLE_APPLY`, `DEMO_2_INELIGIBLE_APPLY`, etc.).
- `GET /api/dbms-lab/run-tests`: Executes 7 automated transaction & trigger test suites.
- `POST /api/dbms-lab/reset-db`: Atomically resets and re-seeds the entire database.
